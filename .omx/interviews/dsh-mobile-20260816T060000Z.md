# DSH Mobile Interview Summary

## Decisions

1. Implement only the Flutter mobile client in its own Git repository.
2. Use public documents as the cross-team contract, aligned to the current Relay implementation.
3. Use Flutter 3.x and verify iOS plus Android builds.
4. Authentication uses email and password.
5. The app uses the supplied DSH product UI as its visual source of truth and ships a fixed light theme.
6. The app may use a Mock data source until Relay deployment is available.

## Pressure pass

The initial visual assumption favored the dark Harness marketing site. The supplied DSH product screenshot showed that the real product uses a light, dense tool interface. The decision was revisited and changed to a fixed light theme.
